6) ФИКС (2026-06-20): оружие застревает в режиме «Закрыто» (NonInteractable)
   после перезарядки В КОНТЕЙНЕРЕ.
   Файл «только локально»: Lua/Autorun/ng_reload_lock_fix.lua (НОВЫЙ).
   Причина: анимированная перезарядка AAAC при вставке магазина безусловно
   бьёт ТРЕМЯ блокировками сразу (напр. M4.xml:404, target="This,Character,
   Contained"): ствол -> NonInteractable; его контейнеры -> AllowAccess=false
   (окно слота не открыть); магазин внутри -> NonInteractable («закрыто»).
   Снятие висит на условии навыка ПЕРСОНАЖА (skillrequirement weapons lt/gte
   45). В мировом контейнере персонажа нет -> ничего не снимается -> ствол,
   доступ к контейнеру И магазин остаются заблокированы навсегда. Резервный
   сброс (Always OneShot, ~346-350) одноразовый и только пока предмет активен
   -> подбор в руки не лечит. NonInteractable сохраняется в сейв -> остаётся
   после перезагрузки. Одинаковый баг на всех ~44 стволах.
   Фикс (generic, без правки XML каждого ствола): полностью снимает все три
   слоя для RangedWeapon, не принадлежащего персонажу — ствол NonInteractable,
   AllowAccess=true на ВИДИМЫХ контейнерах (скрытые прокси drawinventory=false
   пропущены), NonInteractable=false с МАГАЗИНА. ВАЖНО: технические предметы
   внутри (repair, weapons-up, *reloading/*chamber) НЕ разлочиваются — наоборот,
   держатся NonInteractable=true (repair снять = сломать ствол). Два входа:
     * Hook.Patch ItemContainer.OnItemContained — новая перезарядка в контейнере
       (снятие через 3с, после окна перезарядки);
     * Hook.Add roundStart — лечение уже застрявших/сохранённых стволов (раз за
       раунд, идемпотентно).
   Плюс команда `ng_aaac_unlock` — ручное лечение без перезахода в раунд.
   Только снимает (не ставит); стволы у персонажа не трогает. На сервере И
   клиенте -> MP-safe.

7) ФИКС (2026-06-20): боевая пластина брони пропадает при снятии бронежилета
   или на конце раунда (сейв+загрузка).
   Файл «только локально»: Lua/Autorun/ng_armor_plate_fix.lua (НОВЫЙ).
   Причина: вставленная пластина (ceramic/steel/kevlar) превращается в аффликцию-
   бафф на персонаже (armored_ceram/steel/kevlar=100), а сам предмет-пластина
   удаляется (Guns_enchanced.xml ~58-75). Пока броня надета, OnWearing держит
   armored_proxy=100; при снятии proxy затухает -50/с и при <=25 эффект стирает
   armored_X (Afflictions.xml ~253-258). Предмет уже потреблён -> пластина
   потеряна. То же на конце раунда/загрузке. Кнопка «Take off plate» возвращает
   пластину, но только неповреждённую (armored_X gte 96) и вручную.
   Фикс (v3, проверен): С СОХРАНЕНИЕМ ИЗНОСА (выбран вариант «честно по износу»).
   Пластина-предмет несёт остаток прочности как Condition, ре-вставка
   восстанавливает ровно эту силу -> изношенные пластины тоже спасаются БЕЗ
   эксплойта. Три серверных триггера:
     * ОПРОС (Timer.Wait 0.5с, guard поколения): если у персонажа есть бафф
       пластины, но бронежилет НЕ надет (OuterClothes пуст) -> вернуть. Ловит
       снятие/в руки/выброс, работает ВНЕ операций с инвентарём (без re-entrancy);
     * Hook.Add roundEnd — все ещё надетые пластины до сейва;
     * ПЕРЕОПРЕДЕЛЕНИЕ ВСТАВКИ (Hook.Patch ItemContainer.OnItemContained): ваниль
       ставит бафф=100, через 120мс меняем на Condition вставленной пластины ->
       ре-вставка изношенной даёт её реальную силу, а не 100.
   Возврат: спавн пластины с condition=сила баффа, затем снять бафф (сначала спавн,
   снимаем при успехе). Броня = все 3 типа сразу -> возвращаем все. Порог 1 (износ
   сохраняется, потерь/эксплойта нет). armor-handle/2 НЕ спавним (мусор). Серверная
   логика; MP-клиенты пропускают, синк с сервера. Диагностика: команда `ng_plate`.
   Кнопка «снять пластину» — базовый порог >=96 (не трогали), но авто-возврат её
   заменяет. Пластины ceramic/steel/kevlar-plate определены в XML/attach.xml
   (maxcondition по умолчанию 100 = шкала силы баффа).
   (Провалы по пути — урок: НЕ спавнить/флашить Spawner из хука мутации инвентаря
   (re-entrancy ломала кнопку); Item.Unequip не ловит OuterClothes->руки; enum
   InvSlotType в Lua печатается ЧИСЛОМ, сравнивать через == InvSlotType.X.)
